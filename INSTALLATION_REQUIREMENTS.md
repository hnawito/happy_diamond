# Happy Diamond — installation requirements

This file describes the components needed to install and run the current project. JavaScript dependencies and exact resolved versions are maintained in `package.json` and `package-lock.json`; install them with `npm ci`.

## Required components

| Component | Requirement | Purpose |
| --- | --- | --- |
| Operating system | Windows, Linux, or macOS supported by the installed Node.js and Sharp packages | Hosts the application |
| Node.js | Minimum compatible version: 20.19.0 on the Node 20 line, or 22.12.0 and newer. This project was tested with Node 24.21.0 | Runs the server, build tools, and tests |
| npm | Included with Node.js; this project was tested with npm 11.19.0 | Installs dependencies and runs project commands |
| Persistent disk | Writable directories for private data and product images | Saves customer records, catalog changes, encryption key, and uploaded photos |
| Web browser | A modern browser with JavaScript, cookies, and local storage enabled | Storefront, customer accounts, and admin dashboard |
| Network access during installation | HTTPS access to the npm registry and required package downloads | Installs packages and Sharp's platform-specific native image binaries |
| Node.js hosting | One continuously running application process | Provides authentication, uploads, customer accounts, and catalog APIs |

Static hosting of `dist/` alone is insufficient. No separate database server, Python installation, or manually installed image-processing application is needed for the current implementation. Sharp normally installs its required image-processing binaries through npm; do not disable optional dependencies during installation.

## Application dependencies

The ranges below come from the current `package.json`. `npm ci` uses the exact versions in the lockfile.

| Package | Declared version | When needed | Function |
| --- | --- | --- | --- |
| `nodemailer` | `^10.5.0` | Runtime | Sends recovery emails and customer campaigns through SMTP |
| `sharp` | `^0.35.5` | Runtime | Validates, resizes, and converts uploaded product images |
| `vite` | `^7.0.0` | Development and production build | Serves development assets and creates `dist/` |
| `jsdom` | `^26.1.0` | Automated tests | Checks Arabic/English page text, dynamic translations, RTL direction, and unchanged form values |

Node's built-in HTTP, filesystem, and crypto modules provide the server, JSON storage, password hashing, and personal-ID encryption. They require no additional npm packages.

## Storage and file permissions

| Location | Contents | Deployment requirement |
| --- | --- | --- |
| `data/catalog.json` | Saved product catalog | Persistent, private, readable and writable by the server |
| `data/customers.json` | Customer profiles, password hashes, orders, segments, email templates, campaign records, reset-token hashes, and admin settings | Persistent, private, readable and writable by the server |
| `data/personal-id.key` | Generated key for personal-ID encryption, unless an environment key is supplied | Private, persistent, backed up securely |
| `uploads/products/` | Product photos stored as individual WebP files | Persistent, server writable; photos are publicly served through the application |
| `dist/` | Production frontend build | Generated by `npm run build`; server must be able to read it |
| `email-config.local.json` | Local SMTP settings and site URL | Optional local configuration; excluded from Git |

The server creates the data directory and encryption key as needed. The catalog and customer files are written when changes are saved. Include the existing product-image files when copying this project to another machine.

Back up private data, uploaded images, and the encryption key together, with the key protected separately where possible. Changing or losing the encryption key prevents recovery of previously encrypted personal IDs. Image storage grows as photos are uploaded; removed photos are retained on disk. Uploads accept up to eight images per product, 5 MB per input image, and are converted to WebP with a maximum dimension of 2000 pixels.

Use persistent volumes on hosts that otherwise discard files when restarting or redeploying. The current JSON storage and in-memory sessions support one server process; running multiple instances requires a shared database, session store, and image-storage design.

## Configuration

Set environment variables in the server's launch terminal or hosting configuration. `.env` files are **not loaded automatically**. Restart the server after changing environment variables.

| Variable | Default / format | Use |
| --- | --- | --- |
| `PORT` | `5173` | Application's listening port |
| `COOKIE_SECURE` | `false`; set to `true` with HTTPS | Requires authentication cookies to use HTTPS |
| `CATALOG_FILE` | `data/catalog.json` | Alternative absolute catalog path; private customer data and the generated key are stored in its parent directory |
| `PRODUCT_IMAGE_DIR` | `uploads/products/` | Alternative absolute directory for product images; public URLs remain `/uploads/products/…` |
| `PERSONAL_ID_KEY` | Optional, exactly 64 hexadecimal characters | Supplies a persistent AES key instead of generating `data/personal-id.key` |
| `ADMIN_PASSWORD_SHA256` | Optional, exactly 64 hexadecimal characters | Sets the initial admin password hash for a new private data store; saved admin password changes take precedence |
| `APP_URL` | Local configuration's `appUrl` | Base URL used in reset and unsubscribe links; set to the real public HTTPS URL for production |
| `ADMIN_EMAIL` | Local configuration's `adminEmail` | Initializes the recovery address for a new private data store; later changes use the dashboard |
| `SMTP_HOST` | Local configuration's `host` | SMTP host, currently configured locally as `smtp.gmail.com` |
| `SMTP_PORT` | Local configuration's `port`, otherwise `465` | Port 465 uses TLS directly; other ports require STARTTLS |
| `SMTP_USER` | Local configuration's `user` | Email-service login |
| `SMTP_PASSWORD` | No default | Email-service credential; Gmail setup uses an app password |
| `MAIL_FROM` | Local configuration's `from` | Sender address and display name |

The temporary Gmail configuration uses `nawito@gmail.com`. Its credential is intentionally absent. For a fresh installation, copy `email-config.example.json` to `email-config.local.json`, update the sender and site URL, and supply the credential through `SMTP_PASSWORD`. Alternatively, supply all mail settings through environment variables. See [EMAIL_SETUP.md](EMAIL_SETUP.md).

Customer accounts, catalog management, and uploads work without SMTP credentials. Email recovery and campaign sending remain unavailable until email is configured. Keep SMTP credentials and encryption keys out of source control.

## Local installation — PowerShell

Open PowerShell in the project folder, then run:

```powershell
node --version
npm --version
npm ci
npm test
npm run dev
```

Default local addresses:

- Storefront: `http://localhost:5173/`
- Administrator: `http://localhost:5173/admin.html`
- Customer registration and account: `http://localhost:5173/account.html`
- Password recovery: `http://localhost:5173/recovery.html`

If port 5173 is occupied, choose another before starting:

```powershell
$env:PORT = '5174'
npm run dev
```

Set `APP_URL` or the local configuration's `appUrl` to the same address if using email links. Sign in with the admin password supplied during setup, or the saved replacement password.

## Production installation

1. Copy the source, `package.json`, `package-lock.json`, and existing `uploads/products/` files to the host. Preserve or restore private data and its encryption key separately.
2. Run `npm ci`, `npm test`, and `npm run build`. Development dependencies must be installed during the build because Vite is needed.
3. Configure the data and image locations as persistent writable directories.
4. Set the public `APP_URL`, email settings, and `COOKIE_SECURE=true`.
5. Run `npm start`. Keep the Node process running using the host's service manager. Configure automatic startup and restart there.
6. Route the public domain to the application through an HTTPS reverse proxy or managed HTTPS service. Forward the real host and original origin consistently so same-origin write protection works.
7. Serve public files through this application. Do not publish the source folder, `data/`, SMTP configuration, or key files as a static directory.

Keep the application port reachable only through the intended local network or reverse proxy. Allow outbound SMTP traffic to the configured mail service (Gmail setup: TCP 465) and HTTPS access for any remaining external homepage images and Google Fonts.

## Installation acceptance checks

- `npm test` and `npm run build` complete successfully.
- Storefront, admin login, customer registration, and recovery pages load.
- Admin can save a product and upload a JPEG, PNG, or WebP image; it appears in the storefront.
- Product changes and image files remain available after restarting the server.
- Customers can see only their own order history.
- Private data, keys, and SMTP configuration are not accessible through public URLs.
- Once SMTP is configured, a reset link reaches the intended mailbox and uses the correct public URL.
- Backups include both private data and uploaded photos.

Current payment behavior: customers submit unpaid order requests; admins can record completed purchases. There is no payment gateway or online card processing to install in this version.
